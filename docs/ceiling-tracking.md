# True Peak ceiling tracking — 2026-10-14

The previous final reconstruction guard reserved 0.5 dB below the requested ceiling on every signal. That reserve, rather than a meter offset, explains a roughly -1.0 dBTP output when the ceiling is -0.5 dBTP. Merely changing the reserve to 0.25 dB failed the independent adversarial reconstruction tests.

The replacement has two signal-aware, stereo-linked lookahead stages. The first predicts the incoming reconstructed waveform using 128 taps and 16 phases. The second reconstructs the first stage's actual gain-modulated output using 128 taps and 8 phases, and corrects any remaining reconstructed peaks. Both retain the beta=10 Kaiser-windowed sinc kernel, a 64-sample linear lookahead attack, a 128-sample reconstruction-support hold, and a 32 ms release. Their respective small reserves are 0.02 and 0.06 dB. Both stages target the requested ceiling, so the reserves must not be described as an unconditional 0.08 dB output attenuation. Measured saturated steady tones remain approximately 0.06 dB below the ceiling.

This is waveform reconstruction and predictive gain control; it does not clip individual samples or modify the displayed True Peak value. Quiet signals retain unity gain. Reductions remain linked across channels. The reported guard gain includes the first-stage reduction delayed to the samples leaving the second stage.

The guard's latency increases from 191 to 382 samples, an additional 3.979 ms at 48 kHz. `OversamplingEngine` adds the guard's declared latency to its path latency. Hosts need the updated plugin latency report.

## Validation

- Existing `TruePeakGuardTests`: all 768 float/double adversarial cases pass with the unchanged ceiling +0.1 dB criterion. Worst independent 16-phase / 96-tap beta=9 reconstruction excess: **+0.079303 dB**. The steady sample-peak check is strengthened from greater than -1.02 dBFS to greater than -0.60 dBFS at a -0.5 dBTP ceiling. Real-time allocation, reset allocation, stereo-ratio and impulse-latency checks remain in place.
- Separate offline rerun of all 768 adversarial cases against 20-phase / 128-tap beta=9 reconstruction: worst excess **+0.063997 dB**. This reference uses a different phase count and window from the production predictor and does not reuse production coefficients.
- New `CeilingTrackingTests`: 62 independent 20-phase / 128-tap cases pass across float/double, 44.1–192 kHz, -3/-0.5/0 dBTP ceilings, saturated 997 Hz tones, and near-Nyquist bursts up to amplitude 200. Worst steady headroom is **0.059959 dB**; worst burst excess is **+0.044882 dB**. Cropped steady excerpts are reconstructed only where their entire FIR support lies inside the excerpt; this avoids introducing artificial hard cuts at the crop boundaries. Burst tests include their actual full delayed tails.
- The same new test compares scalar and SSE2 stage outputs and gains across 65,536 random/burst frames with 8 and 16 phases. Maximum difference: **6.661e-16**, below the required 1e-10 threshold. It also checks that the public reduction value matches the corresponding output samples in float and double.

SSE2 evaluates every original double-precision coefficient and every phase using four vector accumulators. The scalar fallback remains available on other architectures and in the comparison test. There is no lower-tap, lower-phase or fast-math path. In one local MSVC `/O2` guard-only benchmark processing 1,920,000 stereo frames at 192 kHz, the old scalar 8-phase guard took 1.256 s (RTF 0.1256); the final two-stage guard took 1.397 s (RTF 0.1397). The earlier scalar two-stage prototype took 3.682 s. These are local guard-only timings, not a CPU guarantee or a measurement of the complete plugin.

The stated overshoot criterion is a tested +0.1 dB reconstruction tolerance, not an all-input mathematical ceiling guarantee or a certification against a loudness standard. Different reconstruction filters, arbitrary pathological near-Nyquist content and parameter changes can produce different readings. Full plugin integration, host latency/validation, the approved music file, subjective distortion and Ozone comparison must be evaluated separately.
